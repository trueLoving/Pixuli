# 性能边界与列表策略

- **文档版本**：1.5
- **日期**：2026-10-08
- **关联**：REF-603 · [#132](https://github.com/trueLoving/Pixuli/issues/132) ·
  [PLANS.md](../../PLANS.md)
- **产品约束**：本地工作区为 SSOT；远端可选同步；主路径为「添加 → 同步 → 复制链接」
- **实现盘点基准**：与当前工作区代码对照（见 §四）

> 本文回答四件事：**(1) 各端应关注什么（及共性）**；**(2) 用什么设计/算法逼近目标**；**(3) 如何测量与验收**；**(4) 代码上已实现 / 部分实现 / 未做**。

---

## 0. 目标一句话

在 **1k～数万** 资源规模下，保证：

1. **首屏可交互**（列表可滚动、可点选），不为「缩略全部就绪」而阻塞；
2. **滚动流畅**（主线程不被解码/IO 打爆）；
3. **同步可预期**（显式 pull/push 有进度、可取消、不锁库浏览）；
4. **内存有上限**（缩略、预览、解码并发受控，崩溃前先降级提示）。

不追求：全库瞬时缩略完成、远端 raw 热路径零延迟、未声明的网格/任务抽屉性能。

## 一、应关注什么：共性 vs 分端

### 1.1 三端共性（必须先对齐）

这些逻辑应落在 **共享层**（`app` 业务 + `@pixuli/core/vault`），避免 Web /
Desktop / Mobile 各写一套：

| 共性关注点         | 为什么共同                                    | 当前/目标落点                                         |
| ------------------ | --------------------------------------------- | ----------------------------------------------------- |
| **索引驱动列表**   | 首屏只读本地索引，不扫全盘 blob、不拉远端全库 | LocalVault / index；UI 吃 `ImageItem[]`               |
| **可视区渲染**     | DOM/原生列表都不能挂载数万节点                | 文件表虚拟窗口（`virtualWindow`）；网格若恢复需同策略 |
| **缩略节流**       | 解码与 IO 是大头，与端无关                    | LRU + 并发上限；仅窗口内请求                          |
| **范围缩小**       | 文件夹 / 搜索 / 查询降低工作集                | 选文件夹清查询；大库提示引导缩小范围                  |
| **同步与浏览解耦** | 同步慢不应锁库                                | 显式 sync；角标 N；后台任务不阻塞列表                 |
| **阈值与文案**     | 产品对「大」的定义应一致                      | `libraryScale`：500 / 5 000                           |
| **降级顺序**       | 先保交互，再保观感                            | 见 §二优先级                                          |

**共同原则**：热路径 =
**索引 + 可视区 + 限流**；冷路径 = 全量扫描、全量缩略、远端全量 list、AI 等。

### 1.2 Web（浏览器 / PWA）——优先关注

| 关注点                  | 说明                                       | 风险若不做                     |
| ----------------------- | ------------------------------------------ | ------------------------------ |
| **主线程预算**          | 单线程；大 JSON 解析、pdf.js、视频取帧易卡 | 滚动掉帧、输入延迟             |
| **FSA / OPFS IO**       | 句柄权限、目录遍历成本；刷新后重授权       | 首屏假死、重连摩擦             |
| **内存与标签页回收**    | Blob URL、缩略缓存、Worker                 | 标签页被杀、预览失败           |
| **网络仅在同步/复制链** | 列表不依赖网络；online 横幅非主路径        | 误导用户以为「要联网才能用库」 |
| **SW / 安装壳**         | 可选；**不**承担资源库离线真相             | 与本地 vault 职责混淆          |

Web **不必优先**做：系统级后台队列、托盘、原生文件监视（属 Desktop）。

### 1.3 Desktop（Electron）——优先关注

| 关注点               | 说明                                      | 风险若不做           |
| -------------------- | ----------------------------------------- | -------------------- |
| **真实磁盘大目录**   | `scan` / 监视器、路径编码、杀毒软件干扰   | 扫描卡死、索引不完整 |
| **进程分工**         | 重解码/AI 进 worker 或 utility；UI 进程轻 | 整窗无响应           |
| **长期会话内存**     | 用户常开数小时；缩略与预览泄漏更致命      | 内存单调上涨         |
| **同步队列（后续）** | 离线时积压 push（#88），与列表解耦        | 恢复网络后洪峰       |
| **本地预览成本**     | `file://` / 原生路径大图解码              | 预览打爆内存         |

Desktop **可延后**：PWA 安装提示、浏览器配额话术。

### 1.4 Mobile（Capacitor）——优先关注（共享 UI，约束更紧）

| 关注点                  | 说明                                     | 风险若不做              |
| ----------------------- | ---------------------------------------- | ----------------------- |
| **更低内存 / 热**       | 同逻辑更易 OOM；WebView 差异大           | 闪退                    |
| **触控滚动 + 虚拟列表** | 与键鼠同一数据源，交互不同               | 滚动跳跃、选中错位      |
| **取帧/PDF worker**     | Android WebView 对 blob、worker 路径敏感 | 缩略全失败              |
| **沙箱存储**            | `mobile://` 应用数据；卸载即清           | 用户预期与 Desktop 不同 |
| **电量与后台**          | 避免定时全库扫描                         | 耗电、被系统杀          |

Mobile **与 Web 共享**列表/缩略策略；**差异**在适配器 IO 与 WebView 能力矩阵。

## 二、用什么手段达到目标

按 **投入产出** 排序；未标注「已落地」的为后续选项。

### 2.1 架构与数据流（设计）

| 手段             | 做法                                            | 收益                         |
| ---------------- | ----------------------------------------------- | ---------------------------- |
| **索引 SSOT**    | 列表/搜索读 vault 索引；blob 按需               | 首屏与 N 解耦                |
| **分层加载**     | 元数据一行 → 可见缩略 → 点开再解码原片          | ✅ deferPreview + AssetThumb |
| **同步管道独立** | SyncEngine 队列；UI 只订状态（pending N、冲突） | 浏览与同步互不阻塞           |
| **范围默认小**   | 默认当前文件夹；「在全部中搜索」显式            | 工作集可控                   |
| **能力降级表**   | 超阈值：提示 → 禁昂贵统计 → 拒全库缩略          | 失败可预期                   |

### 2.2 列表与渲染（算法 / UI）

| 手段                  | 做法                                            | 状态                 |
| --------------------- | ----------------------------------------------- | -------------------- |
| **行虚拟窗口**        | `start/end + overscan`；只挂载可见行 ± overscan | ✅ 已落地            |
| **固定行高**          | 简化窗口计算（当前 44px）                       | ✅                   |
| **搜索/筛选在索引上** | 避免对 blob 做全文                              | ✅ 查询子集          |
| **网格虚拟化**        | 二维窗口或回收池                                | 网格主视图恢复后再做 |
| **窗口回收缩略**      | 离开可视区释放 / 保留 LRU                       | 部分（LRU ✅）       |

### 2.3 缩略与媒体（算法 / 限流）

| 手段                 | 做法                             | 状态                 |
| -------------------- | -------------------------------- | -------------------- |
| **并发池**           | 同时解码 ≤ 3                     | ✅                   |
| **内存 LRU**         | 缩略条目 ≤ 120                   | ✅                   |
| **懒加载属性**       | `loading="lazy"` + 仅窗口内挂载  | ✅                   |
| **类型降级**         | 视频/PDF 失败 → 类型图标         | ✅ 方向              |
| **持久缩略磁盘缓存** | 按 content hash 落盘，刷新免重算 | 待做                 |
| **Worker 解码**      | 大图/PDF 移出 UI 线程            | Desktop/Web 按需加强 |

### 2.4 IO 与同步（分端适配，共享契约）

| 手段      | Web                                              | Desktop                | Mobile             |
| --------- | ------------------------------------------------ | ---------------------- | ------------------ |
| 列目录    | FSA/OPFS 增量、避免反复 `requestPermission`      | `fs` 扫描 + 可选 watch | 沙箱 Directory API |
| 远端 list | 同步时用；契约已有 `page/pageSize`，实现待真分页 | 同左                   | 同左               |
| 冲突/重试 | 用户可见结果；退避                               | 可加离线队列           | 弱网提示           |

**调研结论（远端 listImages）**：GitHub/Gitee 现实现仍偏「拉树后拼全量」；仓库列表 API 已分页。资源库首屏**不依赖**远端全量 list，故远端真分页属**同步侧**增强，不挡本地大库列表验收。

### 2.5 产品层手段（非纯工程）

| 手段           | 说明                     | 状态                  |
| -------------- | ------------------------ | --------------------- |
| 大库提示       | >500 / >5 000 状态栏文案 | ✅                    |
| 引导缩小范围   | 文件夹树 + 搜索          | ✅ 能力在；文案已提示 |
| 不同步自动上云 | 避免「每改一张就打 API」 | ✅ 产品心智           |

## 三、如何测量与验证

### 3.1 指标（测什么）

| 指标           | 定义                             | 目标（开发机 / 本地库，可修订）               |
| -------------- | -------------------------------- | --------------------------------------------- |
| **TTI 列表**   | 从进入资源库到表格可滚动、可点选 | \< 3s（冷启动，**不含**全量缩略）             |
| **滚动流畅**   | 快速拖动时主线程长任务           | 尽量避免 \> 50ms 的连续阻塞；主观「不明显卡」 |
| **内存水位**   | 打开库 → 滚到底 → 静置           | 相对基线增长可控；无单调泄漏                  |
| **缩略完成率** | 可见区缩略成功比例               | 可见区优先；允许屏外失败/延后                 |
| **同步不锁库** | sync 进行中能否浏览/选中         | 必须可以                                      |
| **规模档位**   | 500 / 5 000 提示是否出现         | 单测覆盖阈值；手工大库抽检                    |

### 3.2 手段（怎么测）

| 手段                                          | 用途                                       | 谁做                  |
| --------------------------------------------- | ------------------------------------------ | --------------------- |
| **单元测试**                                  | 虚拟窗口边界、`libraryScale` 阈值          | CI（`pnpm test`）     |
| **手工场景表**                                | 见 §3.3；Web 必测，Desktop/Mobile 抽测     | 发版前 / Sprint 验收  |
| **浏览器 Performance**                        | Web：长任务、布局、内存采样                | 开发自测              |
| **Chrome/Edge 任务管理器**                    | 标签页 JS 堆                               | Web                   |
| **Electron `process.memoryUsage` / 系统监视** | Desktop 长会话                             | Desktop               |
| **Android Studio Profiler**                   | Mobile 内存与帧                            | Mobile                |
| **固定 fixture（后续）**                      | 约 1k 文件的本地工作区（可脚本生成小文件） | 压测专用；未强制进 CI |

暂不强制：自动化 FPS 录制进 CI（成本高，收益低于手工 + 单测）。

### 3.3 验收场景表（建议 checklist）

| #   | 场景                         | Web  | Desktop | Mobile | 通过标准               |
| --- | ---------------------------- | ---- | ------- | ------ | ---------------------- |
| 1   | 空库 → 添加 20 张 → 列表可点 | ✓    | ✓       | ✓      | TTI 体感正常           |
| 2   | 当前文件夹 ~600 项，快速滚动 | ✓    | ✓       | 抽测   | 提示 large；无明显卡死 |
| 3   | 工作区 \>5 000（或模拟计数） | ✓    | 抽测    | —      | 提示 huge；仍可滚动    |
| 4   | 同步 push 进行中浏览/多选    | ✓    | ✓       | 抽测   | 不锁库                 |
| 5   | 刷新后 FSA 重连再进库        | ✓    | —       | —      | 重连后列表恢复         |
| 6   | 长会话滚列表 10 min          | 抽测 | ✓       | —      | 无持续涨内存至不可用   |

### 3.4 与 Issue 验收对齐（REF-603）

| 验收项                         | 状态                                                            |
| ------------------------------ | --------------------------------------------------------------- |
| 文档含明确数字与策略表         | ✅ 本文                                                         |
| 至少 1 项 P0（分页或虚拟滚动） | ✅ 文件表虚拟窗口                                               |
| 1k 场景可接受（SLA）           | ✅ 定义 TTI\<3s；正式 1k fixture 压测可另开，不挡文档与提示落地 |
