> **一句话**：本地文件库 + 显式同步 +
> **复制可得的外链**。文件夹与文件的查询 / 添加 / 删除 / 修改 / 类型化工具**只改本机**；连接用于同步通道；**外界能否打开某链接由资源位置（本机 / 远端）与云端访问策略共同决定**，Pixuli 不模拟独立的「发布」流程。

本文定 **UI 信息架构、硬规则、默认行为与实现优先级**，不定 Provider API。

用户只记三句：

1. 改库 = 只动本机
2. 要远端一样 → 点同步
3. 要给人看 →
   **复制链接**（仅本地时先同步；能否被外人打开取决于仓库/云服务策略）

## 一、概念与硬规则

### 1.1 用户概念

```text
工作区（Vault）
  └── 资源（文件 + 元数据 + 预览）· 放在文件夹里
        ├── 连接（连到哪个存储、怎么同步）—— 设置里配置
        └── 外链（外界能否打开）—— 由「本机/远端」+ 云端策略决定，非库内编辑字段
```

| 概念         | 用户理解                                                     |
| ------------ | ------------------------------------------------------------ |
| **工作区**   | 本机本地库                                                   |
| **文件夹**   | 本地路径容器；定浏览范围                                     |
| **连接**     | GitHub / Gitee / …（设置中管理；P0 不占活动栏）              |
| **外部访问** | 外人拿到链接后能否打开；**不由 Pixuli 单独「发布」一步改变** |

### 1.2 本地 vs 远端（硬规则）

| 操作                              | 范围           | 自动同步远端？         |
| --------------------------------- | -------------- | ---------------------- |
| 查询 / 浏览 / 预览                | 本地           | 否                     |
| 文件夹新建 / 重命名 / 移动 / 删除 | **仅本地**     | **否**                 |
| 文件添加 / 删除 / 改元数据 / 移动 | **仅本地**     | **否**                 |
| 压缩 / 转换（图片）               | **仅本地**产物 | **否**                 |
| **同步** pull / push              | 本地 ↔ 远端   | 是（**单独入口**）     |
| **复制链接 / 分享**               | 只读展示 URL   | 否；不触发远端状态变更 |

确认文案写清「仅本机」。**不**在删改确认里勾选「同时删远端」。同步态在条目 /
Inspector **只读**展示。

**添加 ≠ 上传到云**：「添加 / 添加到工作区」只表示入库本机；远端一致只通过「同步」。禁止「上传成功 / 已同步到云」类文案暗示已上云。

**同步 ≠ 外网可访问**：文件推到 GitHub 公开仓库后，raw 链接通常即可被外人打开——这是**仓库/云服务策略**，不是 Pixuli 里再点一次「发布」才生效。私有仓库则链接往往需要鉴权，Pixuli 也应如实说明，而非假装能改可见性。

### 1.3 设计原则

| 原则                     | 说明                                                                                             |
| ------------------------ | ------------------------------------------------------------------------------------------------ |
| 本地工作区是主舞台       | 浏览与库内操作默认读/写本地                                                                      |
| 同步 ≠ 外网可访问        | 远端有副本 ≠ 外人一定能打开；访控在云端，不在库内「发布」一步                                    |
| 复制链接即分享主路径     | 无独立发布向导；需要外链时复制即可（先同步若仅本地）                                             |
| 文件夹定范围，查询再收窄 | 可见结果 = 当前文件夹 ∩ 查询                                                                     |
| 类型决定操作集           | 图片可压缩/转换；PDF 等无；无能力则**隐藏**或禁用并说明                                          |
| 能力驱动 UI              | 仅当 provider 真有 `shareLink` / `timedAccess` 等才露对应控件；GitHub/Gitee 典型只有 `publicUrl` |
| 降级显式                 | 链接不可用或外人打不开时：原因 + 替代（先同步 / 去仓库改公开性 / 换连接）                        |
| **不向用户暴露实现层**   | 无「索引」「binding」「manifest」等术语；见 §1.5                                                 |
| 三端同一旅程             | 窄屏只改编排（见 [03](./03-three-platform-interaction-spec.md)）                                 |
| 同步不锁库               | 同步进行中可继续浏览 / 添加 / 编辑；改过的文件结束后再同步一次即可                               |
| 主路径宜薄               | 完整矩阵可进 P1；半实现壳层（死按钮、空档位、未接线栏）比没有更吵                                |

### 1.4 添加与同步：两条通道

```text
选文件（多类型 / 批量）
  → 短确认浮层
  → 写入工作区（本地文件）→ 立刻关浮层
  → 活动栏待推送角标 +N（若已配置连接）
  → 用户需要远端一致时 → 点「同步」
       └─ 同步中不锁库；期间又改本地 → 完成后仍待推送 → 再同步一次
```

| 通道     | 用户动作         | 是否碰远端 | UI 要求                                          |
| -------- | ---------------- | ---------- | ------------------------------------------------ |
| **添加** | 「添加到工作区」 | 否         | 短确认；提交后关浮层；进度若需则在壳层，不占模态 |
| **同步** | 活动栏「同步」   | 是         | 青色 busy；角标待推送 N；**禁止**全屏锁死主界面  |

技术上可将变更入 push 队列，产品叙事仍是「添加完成 = 已在本地」。

### 1.5 用户可见边界：不涉及「索引」

应用内部用 `.pixuli/`
下的账本加速列表与同步（技术称**索引**），**用户界面与文案一律不出现该概念**——对用户无操作价值，只会增加「还要维护两份数据吗」的心智负担。

| 用户关心             | 界面可展示（只读）              | 禁止向用户暴露                         |
| -------------------- | ------------------------------- | -------------------------------------- |
| 资源在不在本机库     | 文件、文件夹、展示名            | 「索引条目」「index.json」             |
| 有没有推到远端       | **仅本地** / **已同步**（两态） | `syncState`、`bindingId`、`remotePath` |
| 还有多少没推         | 活动栏 **待推送 N**（一个数字） | 推送队列文件、队列详情（P0）           |
| 外人能否打开链接     | 复制链接 + 简短说明             | 「发布」「已发布」、档位单选           |
| 库列表不对了（极少） | 设置 → 高级：**重新扫描文件夹** | 「重建索引」「修复索引」               |

实现细节（索引、manifest、Vault）见
[04 本地工作区同步](../02-system-design/04-local-workspace-sync.md)、
[06 同步路径与元数据](../02-system-design/06-sync-path-and-metadata-design.md)。

## 二、信息架构

宽屏：活动栏 + 文件夹树 + 主视图 +
Inspector。窄屏：底栏 + 文件夹 / 详情 sheet（互斥）。

### 2.1 主路径（默认）

```text
┌────────┬──────────────┬─────────────────────────┬────────────┐
│ 活动栏 │ 文件夹树     │ 主视图                   │ Inspector  │
│ 资源库 │ 全部         │ 范围 · 查询 · 添加       │ 空/单/批   │
│ 同步 N │ ├ 相册/      │ 列表（本层 ∩ 查询）      │            │
│ 设置   │ └ 文档/      │                          │            │
└────────┴──────────────┴─────────────────────────┴────────────┘
```

| 区域      | 职责                                             |
| --------- | ------------------------------------------------ |
| 活动栏    | **资源库** · **同步**（角标 N / busy）· **设置** |
| 文件夹树  | 选范围；文件夹 CRUD（仅本地）                    |
| 主视图    | 本层文件；查询；添加；多选                       |
| Inspector | 文件夹摘要 / 单文件 / 批量；类型化操作           |

- **连接不占活动栏一级**（P0）：在设置中管理连接。
- 同步：活动栏触发；busy 用**青色**（见
  [05 品牌](./05-brand-visual-ui.md)），与选中紫条区分。
- 主视图默认**列表**；网格切换为 P1。
- 上下文：选中文件 → **复制链接** / 分享（系统分享）/ 删除；无「发布」主按钮。

### 2.2 可升层（非默认）

连接升为活动栏一级、完整同步任务抽屉等 → 见 §十一 P1 / 延后。

## 三、文件夹（仅本地）

| 操作              | 要点                                                                     |
| ----------------- | ------------------------------------------------------------------------ |
| 选中              | 设当前范围；P1 建议清多选、清已生效查询（可留草稿）                      |
| 新建 / 重命名     | 仅本地；重命名时更新工作区内路径（实现侧同步更新内部账本）               |
| 移动              | 仅本地；P0 以对话框 / 编辑内选目标为主；树内拖放为 P1+                   |
| 删除              | 确认：「仅本机，含 N 个文件，不同步删远端」；当前范围被删则回退父级/全部 |
| 空文件夹 / 整库空 | Empty **必须有 CTA**：添加文件 / 新建子文件夹（区别于查询无结果）        |
| 拖放（桌面/Web）  | **P0**：系统文件拖入 = 打开添加确认。库内条目拖到树 / 拖文件夹 = P1+     |

选中文件夹且无文件多选时：Inspector 显示路径与摘要；文件夹操作可在树右键，P1 可沉入 Inspector。**不**显示图片压缩。

**默认**：主视图只列**本层文件**（不含深层），与「全部」区分清楚。

## 四、查询

- 搜索框为**草稿**；**Enter / 搜索**才生效。
- `?` 语法帮助；清除 = 回到当前文件夹下全部文件。
- 语法：裸词 / `name:`（AND）；`kind:`（OR：`image` / `video` / `pdf` /
  `other`）；`size:`（AND，支持比较与单位）。
- 示例：`cover kind:image size:>1mb`
- **主路径可选**：轻量类型切换（全部 / 图片 / PDF），语法进 `?`，二者并存。
- **不做**独立筛选面板 + chip 条。
- 规划（延后）：`tag:`、`path:`、日期字段。排序用独立控件。
- P1 可选：「在全部中搜索」忽略树范围并提示。

## 五、添加 · 删除 · 修改（仅本地）

### 5.1 添加（短确认 → 仅本地 → 关浮层）

支持**多类型**与**批量**；确认后**不阻塞**其它库内交互。

#### 流程

1. 选文件 / 多选 / 拖放（系统文件拖入 = 打开确认）。
2. **短确认浮层**（目标文件夹默认 = 当前树范围）。
3. 主按钮 **「添加到工作区」** → 写入本地文件（工作区可见）。
4. **立刻关浮层**；toast：**已添加到工作区（仅本机）**。
5. 列表出现条目（短暂「处理中」在条目/壳层表达，不锁模态）。
6. 需要远端一致 → 用户之后点 **同步**（见 §5.4）。

```text
选文件 → 短确认 → 关浮层 → 本地可见
                      └→ 待推送 +N → 用户点同步 → 远端
```

#### 确认层字段（按类型）

| 类型        | 确认内容                       |
| ----------- | ------------------------------ |
| 图片 / 视频 | 预览、名称、描述、标签、文件夹 |
| PDF / 其它  | 文件名、可选描述/标签、文件夹  |

混选一批：同一确认壳；列表带类型角标；共享目标文件夹与可选统一描述/标签。不支持的预处理（如压缩）不在添加确认里强行做。

#### 添加后完善元数据

| 规则                       | 说明                                         |
| -------------------------- | -------------------------------------------- |
| **默认关闭**逐张完善       | 避免大批量添加时打断                         |
| 自动进入逐张               | 批量 **≤3**，**或** 确认层勾选「添加后编辑」 |
| 逐张栏                     | 选中首张；Inspector：上一张 / 下一张 / 完成  |
| 批摘要点文件名切单文件编辑 | **始终保留**                                 |
| 精准元数据主路径           | 入库后单文件编辑                             |

#### 明确不做

- 添加浮层内跑完整远端上传进度并锁死界面。
- 添加成功文案暗示已上云。
- 因「正在添加」而禁用搜索、换文件夹、打开其它文件。

### 5.2 删除

单选 / 多选 / 键盘 Delete。确认必须含「仅本机，不会同步删除远端」。文件夹删除见 §三。

### 5.3 修改

| 可改                           | 只读                                                |
| ------------------------------ | --------------------------------------------------- |
| 展示名、描述、标签、移动文件夹 | 尺寸、体积、MIME、时间、同步态、URL、外链可得性说明 |

#### 展示名 vs 磁盘路径

- 用户编辑的是
  **展示名（**`name`**）**，默认**不是**重命名磁盘文件（「重命名文件」若另开，须单独入口）。
- 列表 / Inspector **主标题用**
  `name`；路径 basename（含 timestamp 前缀）仅作次要信息。
- 同步 round-trip **不得**用远端 basename 覆盖已编辑的展示名。

保存只写本地。

| 能力             | 优先级                                         |
| ---------------- | ---------------------------------------------- |
| 单文件移动文件夹 | **P0**（编辑弹层或 Inspector）                 |
| 批量标签         | 已可做                                         |
| 批量移动         | P1                                             |
| 可见性 / 访控    | **不在库内编辑**；由仓库或云服务控制台策略决定 |

同步进行中亦可修改：结果仍以本地为准；见 §5.4。

### 5.4 同步、待推送与「再同步一次」

**同步**是显式动作（活动栏），把本地变更 pull/push 到连接；与「添加」分离。

#### 壳层反馈（对外默认）

| 元素               | P0 行为                                                                        | P1+                          |
| ------------------ | ------------------------------------------------------------------------------ | ---------------------------- |
| 活动栏「同步」     | 空闲可点；进行中 **青色** busy；角标 = **待推送数 N** 或「同步中」             | —                            |
| 条目 / Inspector   | 只读 **两态**：`仅本地` / `已同步`（待推送合并进「仅本地」；数字只看活动栏 N） | 四态角标、逐条「同步中」闪烁 |
| 任务抽屉           | 不做                                                                           | 待推送列表、进度、失败重试   |
| streaming 暂停续传 | 无能力则 **不露出**                                                            | 有 `streaming` 再露          |

#### 同步中不锁库（硬规则）

- **禁止**全屏遮罩或禁用整个资源库。
- 可轻提示：「同步进行中；若继续修改，完成后请再同步一次。」
- **不**为防竞态而冻结全库。

#### 同步期间又改了同一文件

1. t1 开始推送文件 A。
2. t2 用户再次修改 A → **只写本地**，界面立刻为新内容。
3. t1 结束后：若本地已新于远端 → 仍为待推送（对外可显示「仅本地」）。
4. 用户再点 **同步** → 远端对齐到最新本地。

用户心智：**本地随时能改；远端以最近一次成功同步为准；不够新就再同步一次。**

#### 中断与断点

| 能力                     | 交互                                                               |
| ------------------------ | ------------------------------------------------------------------ |
| 取消「写入本地」未完成项 | 始终可做；未完成则不进入资源库列表                                 |
| 取消本次同步推送         | 可做；本地文件保留，回到待推送                                     |
| 暂停 / 继续（字节续传）  | **仅当** manifest 具备 `streaming`（或等价）时露出；否则不画该控件 |

GitHub / Gitee：按「无字节断点」设计。

#### 单文件状态机（实现完整；UI 默认折叠为两态）

```text
添加到工作区
  → （可选）写入中
  → 仅本地
  →（内部待推送）→ 用户点同步 → 同步中（活动栏 busy）
       ├─ 成功且本地未再改 → 已同步
       └─ 期间或之后本地又改过 → 仍仅本地 + 活动栏 N
```

P0：**不**在每条资源上展示「待同步 / 同步中」四态；活动栏 N + 两态即可。P1 可选展开细态或任务抽屉。

## 六、文件操作：按类型

| 能力                                | 图片 | 视频 | PDF | 其它     |
| ----------------------------------- | ---- | ---- | --- | -------- |
| 预览 / 打开                         | ✅   | ✅   | ✅  | 系统打开 |
| 元数据编辑 / 移动 / 复制链接 / 分享 | ✅   | ✅   | ✅  | ✅       |
| **压缩 / 格式转换**                 | ✅   | ❌   | ❌  | ❌       |
| AI 标签（如 Desktop）               | ✅\* | ❌   | ❌  | ❌       |
| 删除（仅本地）                      | ✅   | ✅   | ✅  | ✅       |

AI 未接入前 **隐藏** 入口，避免常驻 disabled。

复制链接是**只读展示**远端 URL（或说明为何暂无可用外链），**不**改变云端访问策略。矩阵为 ❌ 则隐藏或禁用并说明原因。

**压缩 / 转换**：仅图片；本地处理；替换或另存仍在本地；不自动同步。混合多选时跳过非图片并明示。

| 入口                    | 优先级                   |
| ----------------------- | ------------------------ |
| 工具页压缩 / 转换       | 主路径；总开关打开后可用 |
| Inspector「发送到压缩」 | P1；库内不另造压缩工作台 |

| 选中           | Inspector                       |
| -------------- | ------------------------------- |
| 0 + 树为文件夹 | 文件夹摘要                      |
| 1 文件         | 预览 + 信息 + 类型化操作 + 删除 |
| ≥2             | 批量摘要；操作按类型；批量删除  |

## 七、连接与同步

用户只接触两件事：**这个工作区连哪个远端仓库**（设置里配一次）、**何时 push/pull**（活动栏点同步）。其余（内部账本、manifest、队列）对用户不可见。

### 7.1 四层分工（用户只见两层）

```text
┌─────────────────────────────────────────────────────────┐
│ 同步源：连哪个云、哪个仓库、挂在哪（configRoot）         │  ← 设置 · 连接
├─────────────────────────────────────────────────────────┤
│ 触发：用户点「同步」、可选连接后「立即同步一次」         │  ← 活动栏
├─────────────────────────────────────────────────────────┤
│ 行为：push 本地→远端 · pull 远端→本地                  │  ← 用户无感，只见结果
├─────────────────────────────────────────────────────────┤
│ 内部账本（.pixuli/）：列表、展示名、同步标记、队列       │  ← §1.5 不对用户展示
└─────────────────────────────────────────────────────────┘
```

**同步**与**外链**解耦：

| 概念     | 含义                         | 用户动作            |
| -------- | ---------------------------- | ------------------- |
| **同步** | 本地文件树与远端副本是否一致 | 活动栏「同步」      |
| **外链** | 已同步资源的 URL 能否复制    | **复制链接**（§八） |

### 7.2 同步源（连接）

**产品默认**：一个工作区对应
**一个默认同步目标**（0 或 1 个远端仓库）；多连接保留在设置高级项，P0 不强调。

**入口（P0）**：设置 → 连接；不占活动栏一级。

**添加连接（目标体验，P0 方向）**——替代手填 PAT 表单：

| 步骤 | 用户看到                        | 说明                                       |
| ---- | ------------------------------- | ------------------------------------------ |
| 1    | 「用 GitHub / Gitee 登录」      | OAuth（Web）或 Device Flow（Desktop 优先） |
| 2    | 下拉选仓库                      | API 列 repo，免填 owner/repo               |
| 3    | 选分支（默认 main）             | API 列分支                                 |
| 4    | （高级）远端挂载目录 configRoot | 默认仓库根或 `pixuli/`；多数用户可跳过     |

**可消失**：Token 输入框、owner/repo 手填。  
**Deep link（P1）**：从 `github.com/user/repo` 唤起时预填仓库，仍须授权。

连接器能力位（manifest，设置里只读摘要）：`sync.push/pull`、`publicUrl`
等。列表卡：服务 · 位置 · 能力摘要 · 设默认同步目标 / 编辑 / 断开。

GitHub / Gitee：同步后可复制 raw
URL；**仓库公开性在云控制台管理**，Pixuli 不代管。仅本地工作区：须先添加连接并同步后才有外链。

### 7.3 同步触发

| 时机             | 行为                                    |
| ---------------- | --------------------------------------- |
| 添加文件后       | **不**自动 push；活动栏待推送 **+N**    |
| 用户点活动栏同步 | 选择 push / pull / 双向（现有方向弹层） |
| 首次添加连接后   | 可选一次：「是否立即同步？」非强制      |
| 同步进行中       | **不锁库**（§5.4）                      |

连接 = 配好管道；同步 = 用户决定何时对齐。与「添加≠上云」一致。

### 7.4 同步内容（push / pull 边界）

路径模型（D3 **configRoot
1:1**）：工作区相对路径 ↔ 远端相对路径（相对 configRoot）。详见
[06-sync-path-and-metadata-design](../02-system-design/06-sync-path-and-metadata-design.md)。

| 方向     | 同步什么                                                                                 | 不同步什么                                       |
| -------- | ---------------------------------------------------------------------------------------- | ------------------------------------------------ |
| **Push** | 工作区内的**用户文件**（含子文件夹）；各目录 `.metadata/manifest.json`（展示名、标签等） | 整个 **`.pixuli/`** 目录（内部账本、队列、配置） |
| **Pull** | 远端用户文件 → 落盘同路径；manifest → 合并展示名等元数据                                 | 同上                                             |

用户心智：**同步的是文件夹里的文件**，不是应用后台数据库。删改本地文件后 push 才影响远端；pull 用远端覆盖本地文件内容（本地 SSOT 策略见 §5.4）。

**展示名**：存在 manifest（远端）与内部账本（本地）；pull 不得用远端文件名覆盖用户已改展示名（§5.3）。

### 7.5 内部账本（实现说明，非用户界面）

以下为协作者 / 实现对照，**不得进入用户文案**：

| 存储                                 | 作用                                               |
| ------------------------------------ | -------------------------------------------------- |
| `.pixuli/index.json`                 | 本地资源列表、展示名、标签、`仅本地/已同步` 等标记 |
| `.pixuli/config.json`                | 工作区 id、连接引用                                |
| `.pixuli/sync/*`                     | 队列、游标、冲突（P0 冲突 UI 可弱化）              |
| 远端 `{dir}/.metadata/manifest.json` | 该目录下文件的元数据（随 push 写入）               |

关系：**磁盘文件 = 内容 SSOT**；内部账本 = 列表与同步状态的本地汇总；manifest
= 远端元数据汇总。Pull/Push 后由引擎更新账本，用户只见列表与两态标记。

外部工具直接往工作区拷文件时，可用「重新扫描文件夹」（高级）对齐账本，不说「重建索引」。

## 八、外链与复制链接

**同步** = 资源在远端有无副本；**外链**
= 用户能否**复制**一个 URL 给外界——**能否被打开**由资源是否在远端 +
**云端访问策略**（公开仓库 / 私有 / 分享链）决定，不是 Pixuli 内的「发布」动作。

### 8.1 产品立场：不做用户向「发布流程」

| 旧叙事（废止）             | 新叙事（v3.1）                                                |
| -------------------------- | ------------------------------------------------------------- |
| 选通道 → 选档位 → 生成发布 | 需要分享 → **复制链接**（或系统分享）                         |
| 私有 / 仅链接 / 公开档位   | 外链是否可被外人打开，问**仓库是否公开、分享链是否需登录**等  |
| Pixuli 内「撤销发布」      | 若云端无 per-file ACL API，**不假装能撤销**；提示去仓库改策略 |

理由：

1. **访控真身在云端**：GitHub 公开仓库的 raw
   URL 同步后即可被外人访问；私有仓库需 token。这不是应用里点「发布」能改变的。
2. **时长 / 口令 / 细粒度 ACL**：依赖各云 `shareLink` / `acl` / `timedAccess`
   等机制，Pixuli 只能**透传**已有能力，难以做统一产品承诺。
3. **用户路径更短**：图床类场景「同步 → 复制链接」即够用；多一步发布向导易制造「已发布才安全」的错觉。

### 8.2 资源在哪 → 链接是什么

```text
仅本地（未同步 / 无 remotePath）
  → 无稳定公网外链；复制链接禁用或复制本地预览说明
  → 提示：先同步到已连接远端

已同步 + 连接有 publicUrl（如 GitHub/Gitee raw）
  → 复制 provider.getRawUrl(remotePath) 或等价公网 URL
  → Inspector 只读展示；可选一句「能否被外人打开取决于仓库可见性」

已同步 + 连接无 publicUrl
  → 禁用复制公网链；说明原因与替代（换连接 / 去云控制台开分享）
```

### 8.3 按 provider 能力扩展（非默认主路径）

仅当 manifest 声明且 provider 实现真实 API 时，才在 Inspector
/ 设置中增加控件——**不画空壳档位**：

| 能力 manifest | 可做（示例）                  | GitHub/Gitee 典型 |
| ------------- | ----------------------------- | ----------------- |
| `publicUrl`   | 复制 raw / CDN URL            | ✅                |
| `shareLink`   | 创建仅链接分享（若 API 支持） | ❌                |
| `acl`         | per-resource 可见性           | ❌                |
| `timedAccess` | 过期时间 / 口令               | ❌                |

有 `shareLink` / `timedAccess`
的连接器（如未来 OneDrive）：可在**设置 → 连接能力说明**或二级面板提供「创建分享链接」，仍不是资源库主路径的「发布向导」。

### 8.4 UI 要求（P0）

| 场景               | 行为                                                                           |
| ------------------ | ------------------------------------------------------------------------------ |
| 已同步且有公网 URL | Inspector / 右键：**复制链接**；复制成功 toast                                 |
| 仅本地             | 复制链接禁用；「需先同步到已连接仓库」+ 可选跳转同步                           |
| 已同步但仓库私有   | 可复制 URL（自用）；附注「外人可能无法打开，请在 GitHub/Gitee 调整仓库可见性」 |
| 无连接             | 「请先在设置中添加连接」                                                       |

**主路径仅一个分享动作：复制链接**（或系统分享 Sheet）。不做：`PublishDrawer`、per-file「发布 / 撤销」、私有/公开/仅链接档位单选、「已发布」角标。

### 8.5 降心智：已废止的界面元素

以下项在 v3.3 起**不得再出现在用户界面**；实现应收敛为右列。

| 废止（产品）                      | 收敛为                                             | 状态                              |
| --------------------------------- | -------------------------------------------------- | --------------------------------- |
| `PublishDrawer`、发布活动栏入口   | 复制链接                                           | ✅ v3.3 已移除                    |
| `accessPolicyStore`「已发布」标记 | 删除；是否可分享看同步态 + 仓库策略                | ✅ v3.3 已移除                    |
| 连接用途「发布通道」单独叙事      | 连接 = 同步目标；外链 = 复制链接                   | ✅ v3.3 向导仅保留备份 / 默认同步 |
| Inspector 档位 / 生成发布按钮     | 复制链接 + 说明文案                                | ✅ v3.3 已移除                    |
| 条目双角标 + `linkKind` 技术语义  | 单角标 **仅本地 / 已同步** 两态（§1.5、§5.4）      | ✅ v3.3                           |
| 主区「扫描索引」按钮              | 设置 → 工作区 → **高级** → **重新扫描文件夹**      | ✅ v3.3                           |
| 用户文案出现「索引」「重建索引」  | 不提；扫描结果用「新增 N 个文件 / 资源库已是最新」 | ✅ v3.3 i18n                      |

## 九、关键旅程

1. 开工作区 → **添加**文件到文件夹（仅本地，浮层即关）。
2. 需要远端 → 设置中添加连接 → **同步**（不锁库；活动栏见 N）。
3. 同步中又改了某文件 → 结束后仍待推送 → **再同步一次**。
4. 需要给外人看 → 先**同步**（若仅本地）→
   **复制链接**；能否打开取决于仓库/云策略。
5. 库内删改 → 仅本地；再同步才影响远端。
6. （P1）`kind:image size:>1mb` → 发送到压缩 → 本地产物。
